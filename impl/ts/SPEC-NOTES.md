# 仮実装で見つかった仕様の論点

仕様書を実装して気づいた、曖昧な点や決めておきたい点の記録です。

## v0.5 で仕様に反映したもの

v0.4 の仮実装（M1）とレビューで見つかった論点は、v0.5 の仕様に反映しました。変更点の一覧は[仕様書 §0](../../spec/wake-protocol.md#0-v04からの主な変更)を参照してください。

| 論点 | 反映先 |
|---|---|
| TA文面の禁止文字をCc制御文字（LFを含む）に絞り、他の特殊文字は承認画面で可視化する | §10.4、§10.11 |
| 複数行の文面は `\n`（2文字）で表し、表示形式を切り替えても値は変えない | §10.3、§10.4、§10.11、§10.12 |
| ETは通常のHTTP要求・応答を運び、`/wake/` への転送禁止とルート照合はディスパッチ側の責任 | §11.3、§11.5 |
| ETのクエリはパーセントエンコードの大文字・小文字を問わない | §11.2 |
| 同じ名前のヘッダーはHTTPの規則に従い、単一値のフィールドの重複だけ拒否する | §11.4 |
| `location` は同じオリジン内の絶対パス（path-absolute）に限る | §11.4 |
| ヘッダー全体の 8KiB は名前と値のバイト数の合計で数える | §11.4 |
| クエリの違反は `invalid_path`、`EtRequest` / `EtResponse` の形式不正は `invalid_request` | §11.6 |
| Challenge の儀式は呼び出された API で決まり、それに対応する mode で `th` を計算する | §5.5 |
| 時刻は 0〜2⁵³−1 | §4.6 |
| 平文長の上限を復号前に検査し、超過は `too_large` | §8.7 |
| テストベクターの `expectedError` コード一覧と JSON での表し方 | §16 |

## 確認できたこと（v0.4 時点）

- §4.2 の例 `LP(ascii("ab"), ε) = 00000002 6162 00000000` は実装と一致した。
- v0.4 の §10.3 の例（`hashInput` 102バイト、`operationId = 5f1a2b8b…b461`）は、実装、`node:crypto`、`sha256sum` のいずれでも一致した。
- §8.2 の `len(MsgHeader) = 115 + len(context)` は実装と一致した。
- ECDH の共有秘密が `0x00` で始まる場合も、Web Crypto API の `deriveBits(…, 256)` は32バイトを返す（`ecdh.json` に例を収録）。
